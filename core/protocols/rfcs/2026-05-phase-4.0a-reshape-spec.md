## 1. Current v2 Topology

```text
User Query
  → grid/api.py POST /api/think
    → orchestrator.think()
      → mindgraph.retrieve_context()     # READ
      → dcx.think()                      # INTERPRET
      → truth_engine.evaluate()          # VALIDATE
      → woo.judge()                      # GATE
      → mindgraph.learn()               ← DIRECT WRITE (unsafe)
      → mindgraph.stamp_moment()        ← DIRECT WRITE (unsafe)
      → provenance.record()             # LOG
    ← GridResponse returned to user
```

**Critical defect:** `mindgraph.learn()` and `stamp_moment()` execute inside `think()` with no human approval gate. Truth Gate and Woo auto-approve standard responses. The system writes to the graph on every successful query cycle.

**Additional direct-write path:**

```text
POST /api/learn
  → mindgraph.learn()                   ← DIRECT WRITE (unsafe)
```

No validation, no approval, no Woo gate.

---

## 2. Target 4.0a Topology

```text
Human presents canon
  → POST /api/propose
    → orchestrator.interpret()
      → woo.interpret()                  # STRUCTURAL INTERPRETATION
      → truth_engine.validate_consistency()  # GRAPH CONSISTENCY CHECK
      → decision_engine.rank_placement() # ONTOLOGY PLACEMENT
    ← Proposal returned (state: proposed)
    → approval_queue.enqueue()           # PERSISTED

Human reviews proposal
  → POST /api/approve {proposal_id}
    → orchestrator.commit_after_seal()
      → mindgraph.learn()               # ONLY LEGAL WRITE PATH
      → mindgraph.stamp_moment()        # ONLY LEGAL WRITE PATH
      → provenance.record()             # SEALED
    ← CommitResult returned

  → POST /api/reject {proposal_id, reason}
    → approval_queue.reject()
    → provenance.record()               # REJECTION IS PROVENANCE
    ← RejectionResult returned

  → POST /api/revise {proposal_id, corrections}
    → orchestrator.interpret()           # RE-ENTER LOOP WITH CORRECTIONS
    → approval_queue.revise()            # NEW VERSION, LINKED TO ORIGINAL
    ← RevisedProposal returned
```

**No other path writes to Neo4j. Period.**

## 3. Module-by-Module Delta

### 3.1 `grid/orchestrator.py` — MAJOR REFACTOR

| Current | Target | Change |
|---|---|---|
| `think()` — monolithic cycle | REMOVED as entry point | Split into three methods |
| — | `interpret(canon_input) → Proposal` | Read-only cognition |
| — | `propose(interpretation) → ProposalRecord` | Queues for approval |
| — | `commit_after_seal(proposal_id) → CommitResult` | SOLE write authority |
| `_conversation_history` | Retained for DCX context | No change |

**`commit_after_seal()` contract:**

```python
async def commit_after_seal(self, proposal_id: str) -> CommitResult:
    """
    SOLE METHOD authorized to invoke:
      - mindgraph.learn()
      - mindgraph.stamp_moment()
      - Any Neo4j write query

    Preconditions (all must be True or raise CommitForbiddenError):
      1. proposal exists in approval_queue
      2. proposal.state == "approved"
      3. proposal.approved_by is not None (human identity)
      4. proposal.approved_at is not None (timestamp)
      5. truth_verdict.passed == True (re-validated at commit time)

    Postconditions:
      - proposal.state → "committed"
      - provenance record sealed
      - density telemetry updated
    """
```

### 3.2 `decision_engine/` — NEW MODULE

**Purpose:** Ranks ontology placement options for canon input.

**Contract:**

```python
@dataclass
class PlacementOption:
    labels: list[str]
    properties: dict[str, Any]
    relationships: list[dict]
    confidence: float
    reasoning: str

@dataclass
class PlacementRanking:
    options: list[PlacementOption]
    selected: int
    canon_input_hash: str

class DecisionEngine:
    async def rank_placement(
        self,
        interpretation: WooInterpretation,
        existing_context: list[dict],
        consistency_report: TruthVerdict,
    ) -> PlacementRanking
```

**Scoring factors:**

```text
- Label match to existing ontology patterns     (0.3 weight)
- Relationship density to existing nodes         (0.25 weight)
- TruthEngine consistency score                  (0.25 weight)
- Semantic distance from nearest existing node   (0.2 weight)
```

### 3.3 `approval_queue/` — NEW MODULE

**Purpose:** Persistent queue for proposals awaiting human decision.

**Contract:**

```python
@dataclass
class ProposalRecord:
    id: str
    state: ProposalState
    canon_input: str
    interpretation: dict
    consistency: dict
    placement: dict
    proposed_mutations: list[dict]
    proposed_at: str
    approved_by: Optional[str]
    approved_at: Optional[str]
    rejected_reason: Optional[str]
    parent_id: Optional[str]
    version: int

class ApprovalQueue:
    async def enqueue(proposal: ProposalRecord) -> str
    async def approve(proposal_id: str, approved_by: str) -> ProposalRecord
    async def reject(proposal_id: str, reason: str) -> ProposalRecord
    async def revise(proposal_id: str, corrections: str) -> ProposalRecord
    async def get(proposal_id: str) -> ProposalRecord
    async def list_pending() -> list[ProposalRecord]
    async def list_all(limit: int = 50) -> list[ProposalRecord]
```

**Persistence rule:** Proposals stored as JSONL at `data/approval_queue/proposals.jsonl`. Survives runtime restarts. State transitions are append-only — each mutation appends a new line with the full updated record plus a `_transition` field.

**Rejection behavior:** Rejected proposals are NEVER deleted. They become provenance artifacts. Their `proposed_mutations` are preserved for future contradiction analysis.

| `ensure_schema()` — open | No change |

**Enforcement mechanism:** Runtime assertion at top of `learn()` and `stamp_moment()`:

```python
async def learn(self, ..., _commit_token: str = None):
    if _commit_token != self._active_commit_token:
        raise CommitForbiddenError(
            "mindgraph.learn() may only be called from commit_after_seal(). "
            "Direct writes are forbidden under Phase 4.0a doctrine."
        )
```

`_active_commit_token` is a one-time UUID generated at the start of `commit_after_seal()` and cleared on completion. Cannot be guessed or reused.

## 4. State Machine Behavior

### States

```text
proposed   — Interpreted, validated, ranked, queued. No graph mutation.
approved   — Human sealed. Awaiting commit.
rejected   — Human declined. Preserved as provenance artifact.
revised    — Human corrected. New version created, linked to parent.
committed  — Written to Neo4j. MoStarMoment stamped. Irreversible.
```

### Transition Table

| From | To | Trigger | Graph Write | Provenance |
|---|---|---|---|---|
| — | proposed | `POST /api/propose` | NO | YES (proposal logged) |
| proposed | approved | `POST /api/approve` | NO (not yet) | YES |
| approved | committed | `commit_after_seal()` | **YES** | YES (sealed) |
| proposed | rejected | `POST /api/reject` | NO | YES (rejection logged) |
| proposed | revised | `POST /api/revise` | NO | YES (revision linked to parent) |
| revised | proposed | Re-enters interpretation loop | NO | YES |

### Forbidden Transitions

```text
proposed  → committed     (ILLEGAL — skips approval)
rejected  → committed     (ILLEGAL — overrides human decision)
rejected  → approved      (ILLEGAL — must revise, not override)
committed → any           (ILLEGAL — committed is terminal)
any       → committed     (ILLEGAL unless from approved via commit_after_seal)
```

## 5. Commit Authority Law

```text
ONLY commit_after_seal() may invoke:
  - mindgraph.learn()
  - mindgraph.stamp_moment()
  - Any Cypher query containing CREATE, MERGE, SET, DELETE, REMOVE

All other code paths are PROPOSAL-ONLY.
```

**Enforcement layers:**

1. **Commit token** — one-time UUID generated per commit, passed as `_commit_token`, validated inside `mindgraph`
2. **State assertion** — proposal must be in `approved` state
3. **Timestamp assertion** — `approved_at` must be non-null
4. **Re-validation** — TruthEngine re-runs at commit time; stale approvals can fail
5. **Forbidden-behavior tests** — CI/test suite asserts that calling `learn()` without valid token raises `CommitForbiddenError`

## 6. Rollback Mechanics

**Committed mutations are NOT deleted.** Rollback is a counter-commit:

```text
1. Human identifies bad commit via provenance
2. POST /api/propose with rollback intent
   → content: "Reversal of commit {original_id}: {reason}"
   → proposed_mutations: compensating Cypher (e.g., detach-delete the created node)
3. Normal approval cycle
4. commit_after_seal() executes compensating mutations
5. Provenance links reversal to original
```

**No backdoor delete path.** Every graph mutation, including reversals, goes through the full ingestion loop.

---

## 7. Queue Persistence Rule

```text
Proposals persist at: data/approval_queue/proposals.jsonl
Format: one JSON record per line, append-only
State transitions append new records (full snapshot + _transition field)
```

**Survival guarantees:**

- Proposals survive runtime restarts
- Proposals survive process crashes (append-only, no in-memory-only state)
- On boot, `ApprovalQueue.load()` reads JSONL, rebuilds state map, reports pending count

**Garbage collection:** None. The file grows. This is intentional — it is an audit trail. If size becomes an issue (>100MB), archive and rotate, never delete.

## 8. Rejection Behavior

```text
Rejected proposals become provenance artifacts, not deleted memory.
```

Stored with:

```python
{
    "state": "rejected",
    "rejected_reason": "...",
    "rejected_at": "...",
    "proposed_mutations": [...],
    "interpretation": {...},
    "consistency": {...},
}
```

**Why:** Future contradiction analysis needs to know what was proposed AND rejected. A rejected proposal that later becomes canon (after new evidence) reveals epistemic evolution.

## 11. Migration Order

**Sequence avoids runtime breakage — each step is independently deployable:**

```text
Step 1 — Introduce new modules (no behavior change)
         Add: decision_engine/, approval_queue/, density_telemetry/
         All modules exist but are not called yet.
         Existing v2 loop continues to function.

Step 2 — Introduce proposal states (no behavior change)
         Add ProposalRecord, ProposalState, ApprovalQueue.
         Queue starts empty. Nothing writes to it yet.

Step 3 — Add commit token to mindgraph (backward compatible)
         learn() and stamp_moment() accept optional _commit_token.
         Without token, they still work (v2 compatibility).
         Deprecation warning logged on tokenless calls.

Step 4 — Introduce new API endpoints (additive)
         /api/propose, /api/approve, /api/reject, /api/revise, /api/density
         Old endpoints still work. New endpoints are live.
         Both paths coexist.

Step 5 — Wire commit_after_seal() (new path live)
         Orchestrator gains interpret(), propose(), commit_after_seal().
         New endpoints route through new path.
         Old endpoints still work but log DEPRECATION warnings.

Step 6 — Disable direct writes (BREAKING)
         _commit_token becomes REQUIRED in learn() and stamp_moment().
         Tokenless calls raise CommitForbiddenError.
         POST /api/think → 410 Gone.
         POST /api/learn → 410 Gone.
         WS /ws/chat → 410 Gone.

Step 7 — Enable ingestion runtime
         Phase 4.0a is live.
         Forbidden-behavior tests enforced in CI.
         Density telemetry reporting.
         First canon ingestion cycle ready.
```

**Rollback between steps:** Steps 1–5 are additive and can be reverted by removing the new code. Step 6 is the commitment point — after this, v2 direct-write behavior is gone. Step 6 should only execute after Steps 1–5 are confirmed stable.

## 12. Failure Conditions

| Failure | Behavior | Recovery |
|---|---|---|
| Neo4j down during propose | Proposal created with `consistency: {status: "neo4j_unavailable"}` | Re-validate when Neo4j returns |
| Neo4j down during commit | `CommitFailedError` raised, proposal stays `approved` | Retry commit when Neo4j returns |
| Ollama down during propose | Interpretation falls back to rule-based extraction | Re-interpret when Ollama returns |
| Queue file corrupted | Boot fails with explicit error | Restore from last known good backup |
| Commit token reuse attempt | `CommitForbiddenError` — tokens are one-time | Normal — generate new token per commit |
| TruthEngine fails at commit re-validation | Commit blocked, proposal stays `approved` | Human reviews and re-approves or revises |
| Proposal approved but never committed | Stays in `approved` state indefinitely | Human can reject or re-approve; no auto-commit |
| Runtime crash mid-commit | Partial write possible | Provenance gap detected on next boot; human reviews |

**Partial write recovery:** If crash occurs between `learn()` and `stamp_moment()`, the Memory node exists but no MoStarMoment seals it. Boot-time audit detects unsealed memories and flags them for human review.
