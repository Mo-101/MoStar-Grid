### Truth-state fix (the important one)
`DCX TRINITY` reported **SEALED** while only `dcx0` existed. Two defects:

1. `DCXTrinity.connected` returned `len(self._available_models) > 0` — true if
   Ollama held *any* model, including unrelated ones from other projects
   (`qwen3:4b`). DCX could report connected with zero DCX models present.
2. `_probe_dcx` validated `DCX0_MODEL` only, so a host with one third of the
   trinity passed the seal check.
3. The frontend printed `${modelCount} models loaded` where `modelCount` was
   the *configured* count (always 3), not the measured one.

Now:
- `connected` means **Ollama transport reachable** only.
- `DCXTrinity.seal_state()` is the canonical presence state machine —
  `UNREACHABLE | ABSENT | PARTIAL | LOADED`. It can never return `SEALED`.
- `_probe_dcx` (deep `/api/health`) validates **all three** models with a live
  generation each and is the only place permitted to return `SEALED`, else
  `DEGRADED`/`PARTIAL`.
- Both surfaces return evidence: `expected_models`, `present_models`,
  `validated_models`, `missing_models`, `failed_models`, `sealed`, `checked_at`.
- Verified live: `/api/status` → `PARTIAL`, `sealed=false`, missing dcx1+dcx2.
