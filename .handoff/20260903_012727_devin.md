## What was done

- Added woo_judgment parameter to RuntimeManager.execute().
- If woo_judgment[approved] is falsy, execution is denied after governance but before _run, so the native MoScript binary is never invoked.
- Woo denials are persisted as signed/unsigned receipts with a ContractDecision (contract_id=woo.gate, decision=DENY, reason_codes=(WOO_DENIED,)).
- The audit trace includes the full woo_judgment dict, including scores, confidence, afim_floor, and reasoning.
- Replay protection remains in force: the same execution_id + artifact hashes produce the same attestation_id, so a replay of a Woo-gated denied execution is REPLAY_DETECTED.
- Added tests/momind/runtime/test_woo_runtime_bridge.py with tests for approved, denied, missing, and replay cases.
- Updated MOSCRIPT_RUNTIME_SECURITY_QUALIFICATION_V0_2.json to 33/33 and added woo_* properties.

## Why

WooGate is now wired into the RuntimeManager execution path, so a SemanticFrame.woo_judgment can block unsafe native execution before it happens.
