Grid Runtime Audit

Every active endpoint probed against the running service, every startup configuration traced to the file it actually loads. The Grid was carrying three Neo4j configurations for a graph that answers to one — and the two that lost were pointing at an instance that no longer exists.

2026-09-05 · audit run 79 live routes 35 probed 136,551 nodes 58,638 relationships

01The finding under the finding

ecosystem.config.js defined a shared NEO4J_ENV block and spread it into eight apps. PM2 merges env on top of env_file, so that block overrode every app's own settings. It named the Aura instance 2f88895b. That hostname no longer resolves.

$ python3 -c "resolve 2f88895b.databases.neo4j.io" user='neo4j' db='neo4j' -> ServiceUnavailable: Failed to DNS resolve user='2f88895b' db='2f88895b' -> ServiceUnavailable: Failed to DNS resolve

The Grid stayed up only because its PM2 start command loaded that block and then unset it again, variable by variable, before exec-ing uvicorn. Downstream apps had no such escape: CrypSide's own .env holds the correct bolt://127.0.0.1:47687 and was being overwritten by the dead host on every boot.

The live graph is the local Neo4j on the sovereign band — 136,551 nodes, and the holder of the Genesis constitution chain bootstrapped on 2026-08-31. Both halves of the workaround are now gone: no shared block, no unset list. Each service resolves Neo4j from its own env file and nothing overrides it.

02What changed

Eight files. No migration, evidence artifact, or log was modified or deleted; retired values were commented in place with the reason and the date rather than removed.

  • ecosystem.config.js Shared Aura NEO4J_ENV block deleted along with all eight spreads; grid-api's unset wrapper removed with it; frontend VITE_GRID_API_URL corrected to VITE_GRID_API_BASE (nothing reads the former) and dead VITE_NEO4J_BOLT_URL dropped.
  • _apps/grid/.env NEO4J_EXPECTED_HOST/PORT pointed at Aura while NEO4J_URI pointed at localhost, so the health probe compared the live endpoint to a host the Grid never connects to. Expectation now names the real endpoint.
  • _services/runtime/.env Four dead Aura variables commented out, so grid-api no longer has to unset what it just loaded. A stray bare password line that python-dotenv skipped with a warning on every load is now a commented key.
  • core/engines/cypher_guard.py Scoped subqueries CALL (v) { … } were classified UNKNOWN and denied — including the Grid's own health probe. Folded onto the CALL { … } form the classifier already handles. Parsing widened, policy unchanged.
  • scripts/run_live_constitution_composition.py Read NEO4J_PASSWORD straight from the environment and fell back to a dotenv path that does not exist; with the password in the vault it raised KeyError and the proof could not be run. Now resolves through grid.config and the attested vault.
  • core/ops/tests/test_cluster_identity.py Imported NEO4J_PASSWORD from grid.config, where it no longer exists, failing the whole module at collection. Switched to get_neo4j_password().
  • run.sh Started grid.api:app with a PYTHONPATH that cannot resolve it, and checked Neo4j on 7474 instead of 47474. Both corrected; bind changed to loopback to match the PM2 unit.

Ordered by how much they cost you right now. The first three explain the symptoms you reported.

The DCX trinity cannot seal, by construction

needs your call

All three models are present and Ollama answers in 65 ms, but every invocation fails MIND_CONDUIT_NOT_SEALED. The gate reads MIND_CONDUIT_CANONICAL_EVIDENCE.json, and in the generator that writes it, five of the six gate values are string literals — not measurements. fully_sealed can never evaluate true.

scripts/check_mind_invocation_surface.py:392 gates = { "MODEL_BINDING": "CONSTITUTION_DRIFT", # literal "CYPHER_GUARD": "UNVERIFIED", # literal "PROVENANCE_FILTER": "UNVERIFIED", # literal "ATTESTATION_GUARD": "UNVERIFIED", # literal "INVOCATION_SURFACE_GUARD": invocation_state,# computed "HOSTILE_PATH_TEST": "UNVERIFIED", # literal }

MODEL_BINDING's blocker is now demonstrably stale. The evidence file pins the constitution at digest 02913f52…; the document on disk hashes to e797c19c…, and that is exactly what the graph holds. With the credential path repaired, the live composition proof passes against the running graph:

$ python scripts/run_live_constitution_composition.py {"result": "PASS", "constitution_root_count": 1, "valid_chain_count": 1, "competing_valid_chain_count": 0, "topology_chain_count": 1, "digest_conflict_count": 0}
Left as is I did not touch the gate values. The four UNVERIFIED literals carry a deliberate rationale in the hostile-path evidence — isolated HP cases pass; system composition guards remain unverified — and flipping them is sealing the mind conduit, which HP-9 says requires human authorization. That is your decision, not a config cleanup.

The council is empty because of a cluster filter

needs your call

/api/agents returns [] while /watchtower/stats counts 13 and /watchtower/agents lists them by name. The graph holds 14 :Agent nodes. Every one of them has cluster_id = null, and get_agents() matches (a:Agent {cluster_id: 'nairobi-alpha'}).

Agent total: 14 Agent by cluster_id: [{'cid': None, 'c': 14}] Agent names: AlphaMostar, Altimo, Code Conduit, Data Conduit (DCX001), DeepCAL, FlameBorn Writer, Flameborn, Mo, MoLink, RAD-X-FLB, Sigma, TsaTse Fly, Woo-Tak, Woo-Tak

The last commit — load canonical pantheon and govern all 14 agents — projected the pantheon without stamping cluster identity. test_neo4j_nodes_include_cluster_id_property asserts no node lacks cluster_id, and now that the module collects again, it fails on exactly this.

Left as is Two honest fixes: stamp cluster_id on the pantheon projection, or make agent identity explicitly cluster-neutral. Widening the query to match null would be the third, and it is the fallback this codebase keeps refusing elsewhere. Either real fix is a governed graph write, so I left the graph untouched.

The guard was denying the Grid's own health probe

fixed

/api/health reported mindgraph.ok: false on a connected, healthy graph. The sentinel-label query uses the scoped subquery form your Neo4j requires; CypherGuard.classify() read the token after call as a procedure name, got (label), took the empty string before the paren, matched no whitelisted procedure, and failed closed.

"error": "Unclassifiable Cypher denied (fail closed, hash=0bc63366…): UNWIND $labels AS label CALL (label) { MATCH (n) WHERE label IN labels(n) RETURN n LIMIT 1 } RETURN label, count(n) AS present"
Verified Scoped calls now classify READ; a SET inside one still classifies WRITE and a DETACH DELETE still DESTRUCTIVE. Both guard suites pass — 31 in core/ops, 75 in tests/momind.
